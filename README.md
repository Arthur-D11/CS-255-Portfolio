# CS-255-Portfolio
CS 255 System Analysis and Design portfolio featuring the DriverPass project.

## DriverPass Project Reflection

### Project Summary
The client for this project was DriverPass, a company that wanted to help students prepare better for their driving tests. The company wanted an online system where customers could access classes, take practice tests, and schedule driving lessons. They also needed a way for the employees to manage customer information, appointments, instructors, vehicles, and training packages. In this course, I worked on identifying the company's requirements and created a system design that would check off those needs.

### What I did well
I think one thing I did very well in was organizing the information from the DriverPass interview into the business requirements document. I was able to identify the different functional and nonfunctional requirements and I was also able to explain what the system needed to accomplish. I created a Gantt Chart to help organize the project's task and timeline. Creating UML diagrams for project two is another area in which I believe I did well in. The diagrams helped me understand how the system would work and how different users would interact with the system. My activity diagrams would show how people could schedule driving lessons and take practice exams. I also created a sequence diagram to show how the system would communicate with the scheduling service and database when a customer booked a driving lesson.

### What I would Improve on
Thinking back on what I could improve on, I would spend more time reviewing and perfecting my UML diagrams. In project two, I noticed how important it was to make sure that every part was connected correctly and that the diagrams included different situations a user might go through. An example would be when creating the scheduling diagrams, I had to consider what would happen if an instructor or vehicle was unavailable. The system would need to allow customers to choose another time instead of continuing with an unavailable appointment. I would also see if there are other situations that might need more steps like customers experiencing problems with their account or other scheduling issues. Making these changes would help the developer understand the system better.

### Understanding and Implementing User Needs
I carefully reviewed the DriverPass interview and looked for ways to find features the client was looking for in the system. I used this information to create the business requirements document before moving on to the system design. An important requirement was allowing customers to schedule, change, or cancel driving lessons online. DriverPass also needed employees to manage appointments and customer information. I included features in my requirements and UML diagrams to demonstrate how the system would support both the customer and the employees. Understanding the user's needs is one of the most important parts of a system design because the system needs to solve issues the client is experiencing. If those needs aren't met then the developers could end up creating something completely incorrect or creating a system that doesn't work the way the client was expecting.

### My approach to Software Design
In this course, I learned that designing a system requires more than just deciding what features to include. It needs deep understanding of the client needs, organizing requirements, planning the development process, and creating diagrams that explain how the system works. In future projects, I will start by gathering as much information as I can from the client and their needs. I will also identify the system functional and nonfunctional requirements. I will use tools such as Gantt charts and UML diagrams to organize the work and plan how the system should function. I will also spend more time reviewing my diagrams and getting more feedback before moving forward. Working on the DriverPass project allowed me to see the smallest of details that make a massive difference in the final outcome of a system and how it functions. All in all, this course helped me understand the system analysis and design portion of a project and how important planning and communication are when developing software.
